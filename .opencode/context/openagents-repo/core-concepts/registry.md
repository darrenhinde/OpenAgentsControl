# Core Concept: The Registry

**Purpose**: What `built-ai-configs/registry/registry.json` is, who writes which part, how installs use it.

## What it is

The installer catalog. `install.sh` and the `oac` CLI read it to learn which files make up each component and
profile. Two files, same shape: `registry.json` (OpenCode v2, default) and `registry.v1.json` (OpenCode v1; agent
paths point at `built-ai-configs/opencode-v1/agent/**`; also lists v1-only tools and plugins).

Top level keys: `schema_version`, `version`, `repository`, `metadata`, `categories`, `components`, `profiles`, `subagents`.
`components` has the arrays `agents`, `subagents`, `commands`, `tools`, `plugins`, `skills`, `contexts`, `config`.

```json
{ "id": "quick-start", "name": "Quick Start", "type": "context",
  "path": ".opencode/context/openagents-repo/quick-start.md",
  "description": "...", "tags": [], "dependencies": [], "category": "standard" }
```

Optional extras: `aliases` (extra context ids), `files` (skills list every file they ship).

## Who writes what

| Section | Writer |
|---|---|
| `components.agents`, `components.subagents`, `profiles` | generated by `oac build` (`RegistryEmitter`) from `agent-library/**`; never hand-edit |
| `components.contexts`, `commands`, `skills`, `tools`, `plugins`, `config` | hand-maintained; the build carries them through unchanged and normalises JSON formatting |
| `metadata`, `categories`, `version` | hand-maintained, carried through |

`profiles.<id>.components` is a flat list of `type:id` strings resolved from the system and context profile JSON in
`agent-library/profiles/` (context profile entries are registry context ids or globs such as `core/*`).
Adding a context file to a profile means editing a context profile JSON and rebuilding.

## Validation

```bash
bash scripts/registry/validate-registry.sh            # every path exists, every dependency resolves (-v, -f)
bun run scripts/registry/check-dependencies.ts        # deps, profile members, critical files
bun scripts/registry/validate-registry.ts             # TypeScript twin of the bash validator
```

Both of the first two must be clean before merge. Registering or removing a context file: `guides/updating-registry.md`.

## Install use

`oac init --profile <id>` copies each listed component's `path` (plus `files[]`) into the user's `.opencode/`.
`install.sh <profile>` does the same from the registry URL; override with `REGISTRY_URL="file://$(pwd)/built-ai-configs/registry/registry.json"` to test locally.
Details: `guides/oac-cli-install.md`.
