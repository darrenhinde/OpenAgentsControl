# Core Concept: The Canonical Build

**Purpose**: How agents get from one source file to every AI tool. Read this first when working in this repo.

## The flow

```
agent-library/{agents,skills,commands}/**  (+ profiles/**)       hand-written, the only source
        |  oac build   (packages/cli -> packages/agent-compiler)
        v
built-ai-configs/{opencode,opencode-v1,claude-code}/           generated, per host
built-ai-configs/registry/{registry.json,registry.v1.json}     generated agents/skills/commands/profiles + carried-through rest
built-ai-configs/README.md                                     generated index and agent x host matrix
.opencode/{agent,skills,command}/  and  plugins/claude-code/{agents,skills,commands}/   generated byte-identical live mirrors
.oac/build-manifest.json                                       generated ledger (what the build owns, for pruning)
```

One agent = one file with OpenCode-style frontmatter plus an `oac:` block. A skill is a folder
(`skills/<id>/SKILL.md` + its scripts) and a command a file (`commands/[<group>/]<id>.md`), each with an
`oac:` block too: `docs/architecture/SKILLS-AND-COMMANDS.md`. The build strips
`oac:`, adapts the rest per host, writes the registries, and prunes outputs whose source is gone.

## Generated vs hand-maintained

| Generated (never hand-edit) | Hand-maintained |
|---|---|
| `built-ai-configs/**` (except the v1-only assets below) | `agent-library/agents/**`, `agent-library/profiles/{system,context}/*.json` |
| `.opencode/{agent,skills,command}/**`, `plugins/claude-code/{agents,skills,commands}/**` | `.opencode/context/**` |
| `.oac/build-manifest.json` | `plugins/claude-code/{hooks,context,scripts,...}` |
| The `agents`, `subagents`, `skills`, `commands` and `profiles` sections of both registries | The `contexts`, `tools`, `plugins`, `config` sections of both registries (carried through) |
| | `built-ai-configs/opencode-v1/{plugin,plugins,tool}` and non-agent files under its `agent/` (v1-only assets) |

A hand edit to anything in the left column is drift. The drift gate
(`scripts/validation/check-build-drift.sh`, run by `make check-canonical-drift`) does a real
build and fails if any generated file changed. Fix the source, then `make build-canonical`.

## Hosts

| | `opencode` (v2, default) | `opencode-v1` (on request) | `claude-code` |
|---|---|---|---|
| Output | `built-ai-configs/opencode/agent/<id>.md` | `built-ai-configs/opencode-v1/agent/<category>/<file>.md` | `built-ai-configs/claude-code/agents/<name>.md` |
| Live mirror | `.opencode/agent/` (skills: `.opencode/skills/`, commands: `.opencode/command/`) | none | `plugins/claude-code/agents/` (also `skills/`, `commands/`) |
| Registry | `registry.json` | `registry.v1.json` | none (marketplace reads the plugin dir) |
| Layout | flat | nested by category | flat |
| Agent name | the file name; no `name:` | frontmatter `name:` | `name:` from `oac.overrides.claude-code.name`, else `oac.id` |
| Permissions | `permission:` rules enforced, last match wins | same, `task:` keys are the exact `name:` | not expressible; authored `tools:` list required in `overrides.claude-code` |
| Description | `description:` (one line) | same | `overrides.claude-code.description` with `<example>` blocks (lint error without) |
| Delegation text | `subagent(agent="id", ...)` | `task(subagent_type="Name", ...)` | rewritten to Claude names; delegate must itself ship to Claude |
| `temperature` | kept (v2 does not send it) | kept | dropped with a warning |
| Ships when | `targets` omitted (minus `exclude`) | follows `opencode`; or `targets: [opencode-v1]` alone | `targets` omitted (minus `exclude`) |

Details and known v2 gaps: `docs/features/opencode-v1-and-v2.md`. Most agents declare
`exclude: [claude-code]`; only those with a Claude override ship there (see the matrix in `built-ai-configs/README.md`).

## Package layout (`packages/agent-compiler/src`)

| Dir | Role |
|---|---|
| `core/` | `AgentLoader` (parse + schema), `AgentIdResolver` / `DelegationRewriter` (reference resolution), `HostBlocks`, `TargetPolicy` (who ships where), `BuildPipeline` (plan / write / check / prune), `RegistryEmitter`, `ProfileLoader`, `BuildManifest`, `HostsReadme` |
| `adapters/` | `OpenCodeAdapter` (v2), `v1/OpenCodeV1Adapter`, `ClaudeAdapter`; shared `opencode/OpenCodeBaseAdapter` |
| `verify/` | lints run on every build (`lint/capability.ts`, `lint/opencode.ts`) and the host test harness |
| `hosts/` | drivers that build config/argv for real hosts in conformance tests |
| `types.ts` | zod schemas, including the `oac:` block |

`packages/cli/src/commands/` registers `build`, `init`, `add`, `remove`, `update`, `apply`, `doctor`, `list`, `status`.

## Profiles and the registry

System profiles (`agent-library/profiles/system/`: essential, developer, business, full, advanced)
name agents and context profiles; context profiles (`.../context/`) name registry context ids or
globs like `core/*`. `oac build` resolves them into `profiles.<id>.components` (flat `type:id` list)
in each registry. `oac init --profile <id>` reads that list. See `core-concepts/registry.md`.

## Rules of thumb

- Add or change an agent: edit `agent-library/agents/**`, run `make build-canonical`, commit source and output together.
- A new agent must be in a system profile or users cannot install it.
- Never create files under `built-ai-configs/`, `.opencode/{agent,skills,command}/` or `plugins/claude-code/{agents,skills,commands}/` by hand; the drift gate fails, and a build prunes any ledgered file whose source is gone.
- Health check: `make check-core` (see `guides/compiler-development.md`).
