# Context Engineering and Agent-Harness Evaluation: Evidence Base (as of 16 Oct 2026)

Note on sourcing: much of this came from search-result summaries plus full fetches of the key primary sources (Anthropic context-engineering post, Anthropic evals post, arXiv 2602.11988 abstract, arXiv 2607.27250 full HTML, arXiv 2605.10039 full PDF text, arXiv 2610.00917 full HTML). Items marked "(snippet)" were only seen in search summaries and should be checked before quoting. Most academic items are arXiv preprints, not peer-reviewed.

## Q1. What do vendors and practitioners recommend for context engineering, and do context files (AGENTS.md / CLAUDE.md) actually improve outcomes?

### Takeaway
Vendor guidance has settled on "smallest set of high-signal tokens", meaning a small always-on file, progressive disclosure through skills and on-demand docs, compaction, external notes, and subagents that return condensed results. Controlled studies from 2026, however, find that generic context files do **not** reliably improve task correctness. They can cut runtime and tokens, or raise cost by 20%+, depending on the agent. Their clearest value is in stating non-standard, non-inferable conventions and commands. Repo overviews did not help.

### Cited Findings
**Vendor guidance**
- Anthropic, "Effective context engineering for AI agents" (29 Sep 2025). Its guiding principle is to "find the smallest set of high-signal tokens that maximize the likelihood of your desired outcome." It warns about "context rot": recall gets worse as context grows. It recommends a system prompt at the "right altitude", between brittle hard-coded logic and vague guidance; starting minimal and adding instructions only where failures appear; just-in-time retrieval through lightweight references such as file paths (with Claude Code's CLAUDE.md-up-front plus glob/grep-on-demand hybrid as the example); compaction, with clearing old tool results as a low-risk first step; structured note-taking such as NOTES.md and to-do lists; and subagents that may use tens of thousands of tokens but return condensed summaries of about 1,000–2,000 tokens. It also warns against bloated tool sets with overlapping functions — [Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- OpenAI Codex AGENTS.md guide. Codex concatenates AGENTS.md files from global, root and nested directories and stops once the combined size reaches `project_doc_max_bytes`, 32 KiB by default (the sample config raises it to 65536). The fix is to split instructions across nested directories, since nested files load only when working in that directory. `project_doc_fallback_filenames` lets teams reuse files such as CONTRIBUTING.md — [OpenAI Codex docs](https://developers.openai.com/codex/guides/agents-md.md). Third-party guides warn that later-discovered, more project-specific files are the ones that get truncated — [Daniel Vaughan, "AGENTS.md bloat problem", 27 Mar 2026](https://codex.danielvaughan.com/2026/03/27/agents-md-bloat-problem/) (snippet)
- Claude Code skills use progressive disclosure. Only the name and description are in context at startup, SKILL.md loads when the skill is judged relevant, and bundled files load only when referenced — [designrevision guide](https://designrevision.com/blog/claude-code-skills) (community, snippet). One guide reports that the startup skill listing is capped at 1,536 characters per entry and budgeted at about 1% of the context window — [buildthisnow](https://www.buildthisnow.com/blog/guide/mechanics/best-claude-code-skills-2026) (community, snippet, unverified against official docs)
- Community sizing heuristics (not authoritative, and they disagree): 60–120 lines for a project CLAUDE.md; about 100 project-level instructions as a budget; "every line must change agent behavior or be deleted"; put style rules in linters, not CLAUDE.md — [skills.sh writing-claude-md](https://www.skills.sh/redpanda77/skills/writing-claude-md), [claudeskills.info](https://claudeskills.info/skills/ratacat/claude-skills/claude-md-authoring/) (snippet)

**Empirical studies of context files**
- Gloaguen et al., "Evaluating AGENTS.md" (arXiv 2602.11988; v1 12 Feb 2026, v3 29 Sep 2026; ETH Zurich / LogicStar group). It covers SWE-bench tasks with LLM-generated context files and a new set of issues from repos with developer-committed files. Context files "do not generally improve task success rates" and raise inference cost by **over 20%** on average. Agents do follow the instructions. Repository overviews, "despite being popular and recommended by model providers," did not help. Context files are useful for **non-standard coding practices**. The authors' advice is to evaluate any context file rigorously before deploying it — [arXiv 2602.11988](https://arxiv.org/abs/2602.11988). A search summary adds that LLM-generated files *reduced* resolve rates on SWE-bench Lite because agents followed them literally (snippet, unverified)
- Lulla et al. (arXiv 2601.20404, Jan 2026), OpenAI Codex on 124 real PRs across 10 repos. AGENTS.md is associated with a **28.64% lower median runtime** and **16.58% fewer output tokens**, with comparable task completion. The study measured efficiency, not correctness — [arXiv 2601.20404](https://arxiv.org/abs/2601.20404) (numbers from snippet)
- Khatri, "Do Context Files Help Coding Agents?" (arXiv 2607.27250, 28 Jul 2026). It tested Claude Code (Sonnet 4.6) and Codex CLI (GPT-5.5) on 3 Python repos with 15–17 PR-derived tasks, 3 repeats, and 291 runs, comparing none, always-on AGENTS.md, and selective on-demand wiki. Correctness: Claude 53.3% / 55.6% / 55.6%; Codex 58.8% / 56.9% / 52.9% (omnibus p = 1.00 and 0.66). On borderline Codex tasks, *no context* scored 58% vs 42% for both alternatives. Selective delivery cut Claude's cache-creation tokens on 11 of 11 tasks (p = 0.012). On one repo it cut Claude's wall-clock time by about 24% and blind full-suite test runs from 3.67 to 1.67. Codex's process metrics stayed flat (±4%). Near-miss failures came from implementation skill, not missing repo facts. Detecting a 10pp effect needs roughly 120–200 tasks. Limitation: the selective wiki was 10–18× larger than AGENTS.md for 2 of the 3 repos — [arXiv 2607.27250](https://arxiv.org/html/2607.27250v1)
- McMillan, "Instruction Adherence in Coding Agent Configuration Files: A Factorial Study" (arXiv 2605.10039, May 2026). It ran 1,650 Claude Code sessions (16,050 function-level observations) on 2 TypeScript codebases with Sonnet 4.6, Opus 4.6 and Opus 4.7, varying file size from **25 to 500 lines**, instruction position, single vs multi-file architecture, and conflicting instructions. **None** of these had a detectable effect on compliance; the size and conflict nulls are backed by Bayes factors (BF10 0.05–0.10). The biggest effect was **within-session decay**: about 5.6% lower odds of compliance per additional generated function (OR 0.944), with median first omission at function 4. Task identity mattered more than file structure (a 26.2pp gap between two tasks). Without hooks, linters or CI, missed instructions go unnoticed — [arXiv 2605.10039](https://arxiv.org/pdf/2605.10039)
- Descriptive and other studies: "Agent READMEs" analysed 2,303 context files from 1,925 repos — [arXiv 2511.12884](https://arxiv.org/pdf/2511.12884). "Configuration Smells in AGENTS.md Files" catalogues common mistakes — [arXiv 2606.15828](https://arxiv.org/pdf/2606.15828). "Probe-and-Refine Tuning of Repository Guidance" proposes tuning guidance by probing — [arXiv 2606.20512](https://arxiv.org/pdf/2606.20512) (titles only seen; contents not fetched). The AGENTS.md spec (Linux Foundation) is reported in 40,000+ OSS projects — cited in [arXiv 2605.10039](https://arxiv.org/pdf/2605.10039)

### Inferences
- For OAC: a lazily loaded "context discovery" step that fetches generic coding standards (TypeScript style, security patterns) is the kind of content the studies find does **not** improve correctness. The supported use is project-specific, non-inferable facts: unusual commands, non-default tools, house conventions. Generic best practices are largely already known to frontier models.
- Size, position and file-splitting did not matter for compliance at 25–500 lines. So the case for lazy loading rests on **token cost and latency**, not adherence. Its benefit should be measured in tokens and time, not assumed to raise quality.
- Within-session compliance decay suggests that rules which must hold should be enforced mechanically (hooks, linters, CI, verifier subagents), not restated in more context.
- An extra discovery round-trip (a subagent that finds files and the main agent then reads them) adds latency. Khatri's selective mode only cut tokens and did not help correctness. OAC should therefore ablate "context-discovery on vs off vs single always-on file" on its own tasks.

### Gaps
- Google (Gemini CLI, GEMINI.md) and Cursor (rules / .mdc) official guidance was not retrieved in this pass.
- Exact per-condition numbers in Gloaguen et al. (agents tested, resolve deltas) were not in the abstract.
- I found no official Anthropic page stating a numeric CLAUDE.md size limit. The line-count heuristics above are community-sourced.
- I found no study that isolates memory systems (auto-memory) or compaction strategies for coding agents.

## Q2. How are agent harnesses benchmarked, how much does the harness matter, and which eval tools exist?

### Takeaway
The harness is now a first-class variable. Same-model scores swing by 5–30+ points across harnesses, rankings flip by benchmark, and vendor-native harnesses are not reliably best. SWE-bench Verified is considered saturated and contaminated, while SWE-bench Pro and Terminal-Bench 2.x/3 (run via Harbor) are the current reference benchmarks. Anthropic's own eval guidance is to start small: 20–50 tasks drawn from real failures, deterministic graders, outcome-based grading, isolated trials, and pass^k for consistency.

### Cited Findings
**Harness effects**
- "Finding the Right Fit: Model–Harness Interactions across Agent Tasks" (arXiv 2610.00917, 1 Oct 2026) covers 66 configurations: 4 configurable harnesses (OpenHands, DeepSeek Harness, PI, openJiuwen), 5 models (Claude Opus 5, GPT-6 Astra, GLM-5.3, Kimi K3, DeepSeek V4 Pro), and native Codex / Claude Code, on TUA-Bench, ALE-CLI and a 63-task Terminal-Bench 4 subset. Findings: "Model rankings reverse across harnesses." On Terminal-Bench 4, Claude leads GPT by 7.94 points in OpenHands but trails by 30.16 points in PI. Claude Code trails OpenHands for Claude on Terminal-Bench 4, and Codex never gives GPT its top score. Cost does not track score: GPT scored 60.32% at $4.66/task under PI vs 52.38% at $19.94 under DSH. Outcomes often depend on how the harness handles failure (timeouts on hung commands, early stops, resuming cut-off turns). Its recommendation is to evaluate the model, harness and task together and to track cost per task — [arXiv 2610.00917](https://arxiv.org/html/2610.00917v1)
- Terminal-Bench 2.0 leaderboard (Snorkel mirror): NexAU-AHE (GPT-5.5) at 84.7%, Codex CLI (GPT-5.5) at 82.2%, WOZCODE (Claude Opus 4.7) at 80.2%. Opus 4.6 scored 58% on Claude Code vs 62.9% on Terminus 2, and Gemini 3.1 Pro scored 63% on Terminus 2 vs 61.3% on Gemini CLI. Snorkel warns that 2.0 and 2.1 scores are not interchangeable — [Snorkel TB 2.0](https://snorkel.ai/leaderboard/terminal-bench-2-0/), [Snorkel TB 2.1](https://snorkel.ai/leaderboard/terminal-bench-2-1/) (snippet)
- A harness-design survey reports that prompt, middleware and verification changes alone, with the model fixed, moved Terminal-Bench 2.0 from 52.8% to 66.5% — [arXiv 2606.20683](https://arxiv.org/pdf/2606.20683) (snippet). DarwinX's automated harness evolution raised GPT-5.4 (high) from 69.7% to 77.0% — [arXiv 2608.07545](https://arxiv.org/pdf/2608.07545) (snippet; the authors are reporting on their own system)
- A position paper, "Stop Comparing LLM Agents Without Disclosing the Harness" — [arXiv 2605.23950](https://arxiv.org/html/2605.23950v1) (title and snippet only)
- SWE-bench Verified: OpenAI's Frontier Evals team declared it saturated and contaminated and stopped reporting on it. Their audit of 138 tasks that GPT-5.2 consistently failed (64 runs) judged 59.4% of them to have flawed tests, and models could reproduce verbatim gold patches — [Decrypt](https://decrypt.co/359012/openai-benchmark-measure-ai-coding-supremacy-contaminated), [Latent Space](https://hopper.webdirections.org/share/ab61c3866a2f58f7/substack%3Apost%3A188928663). SWE-bench Pro (Scale AI) has 1,865 tasks across 41 repos in Python, Go, TS and JS, split into 731 public, 276 commercial and 858 held-out tasks. Models scoring above 70% on Verified score about 23% on the Pro public split — [morphllm](https://www.morphllm.com/swe-benchmark), [Decrypt](https://decrypt.co/359012/openai-benchmark-measure-ai-coding-supremacy-contaminated) (aggregators; verify against Scale's SEAL page). One analysis reports a 12-point scaffold-vs-standalone gap on Verified — [codesota](https://codesota.com/news/swe-bench-contamination-debate) (snippet)
- Anthropic notes that SWE-bench Verified rose from about 30% to above 80%, and that saturation makes large capability gains look like small score changes — [Anthropic, "Demystifying evals for AI agents", 9 Jan 2026](https://anthropic.com/engineering/demystifying-evals-for-ai-agents)

**Eval methodology (Anthropic, 9 Jan 2026)**
- The post's vocabulary is task, trial, grader and evaluation harness. Start with **20–50 simple tasks drawn from real failures**. Prefer code-based graders and calibrate LLM judges against humans. Grade **outcomes, not paths**, because rigid tool-call-sequence checks are brittle. Use **pass@k** when one success suffices and **pass^k** when consistency matters (75% per-trial gives about 42% pass^3). Isolate trials in clean environments; in one case Claude read git history from earlier trials. Read transcripts to separate agent errors from grader errors. Keep low-pass "capability" evals separate from near-100% "regression" evals, and graduate capability evals into the regression suite once they pass reliably — [Anthropic](https://anthropic.com/engineering/demystifying-evals-for-ai-agents)
- Khatri's power analysis: a 10pp effect needs about 120–200 tasks, and adding tasks helps more than adding repeats — [arXiv 2607.27250](https://arxiv.org/html/2607.27250v1)

**Tools**
- **Harbor** (Laude Institute, the Terminal-Bench team) runs containerized agent trials locally in Docker or on Daytona, Modal or E2B. It has built-in Claude Code, OpenHands, Codex CLI and Aider agents and accepts any container-installable agent. A task is a Dockerfile, an instruction, a solution and tests. Run with `harbor run -d terminal-bench@2.0`; TB 2.0 has 89 hand-validated tasks, and a TB 3.0 repo exists — [VentureBeat](https://venturebeat.com/ai/terminal-bench-2-0-launches-alongside-harbor-a-new-framework-for-testing), [Terminal-Bench paper arXiv 2601.11868](https://arxiv.org/pdf/2601.11868), [mintlify Harbor docs](https://mintlify.com/harbor-framework/harbor)
- Anthropic names **Harbor, Braintrust, LangSmith, Langfuse (OSS, self-hosted) and Arize Phoenix (OSS)**. It does not name promptfoo or Inspect — [Anthropic](https://anthropic.com/engineering/demystifying-evals-for-ai-agents)
- **promptfoo** (MIT) is config-driven and CI-first, and includes red-teaming. **Inspect AI** (UK AISI and Meridian Labs) is built from datasets, solvers, scorers, tools, agents and sandboxes, and suits agentic and safety evals. **DeepEval** (Apache 2.0) is pytest-style — [futureagi roundup](https://futureagi.com/blog/best-open-source-eval-frameworks-2026), [aicoolies](https://aicoolies.com/comparisons/promptfoo-vs-inspect-ai) (vendor-authored roundups)

### Inferences
- OAC's eval framework should treat **harness × model × config** as the unit of comparison and report cost and tokens per task alongside pass rate. Results from one model or host do not transfer.
- To check whether OAC's agents and context actually help, run an ablation (OAC off, OAC-lite, full OAC) on 20–50 real-failure tasks with outcome graders, scaled toward 100+ tasks before claiming small effects. Harbor's task format is a plausible standard to adopt or interoperate with instead of a bespoke runner.
- Grading exact tool-call sequences (for example "did it call context-scout first") is the brittle path-grading Anthropic warns against. Behavioural checks are better kept as regression evals, and capability evals should grade outcomes.
- The local Claude Code environment advertises a `claude plugin eval` command and a `/skill-doctor` report for plugin and skill eval suites. That suggests host-native skill evals now exist, but I did not fetch public documentation for them.

### Gaps
- I could not verify Terminal-Bench 2.0/2.1 rows against the live leaderboards (the numbers come from search summaries).
- Public docs for `claude plugin eval` and for OpenAI's or Google's equivalents were not retrieved.
- I found no head-to-head study of promptfoo vs Inspect vs Harbor for coding-agent evals.

## Q3. Known failure modes of heavy prompt frameworks

### Takeaway
The evidence points to four risks: instruction-following decays as instruction count grows; compliance decays within a session; aggressive "CRITICAL / MUST" wording causes over-triggering on current Claude models; and the always-on token tax of large frameworks is increasingly questioned on models that already plan well. No controlled study isolates "MUST-invoke-skill" coercion specifically.

### Cited Findings
- IFScale (Jaroslawicz et al., Distyl AI, arXiv 2507.11538, NeurIPS 2025) tested 20 models from 7 providers. Even the best scored only **68% at 500 simultaneous instructions**. Decay patterns differ: threshold (o3, gemini-2.5-pro), linear (gpt-4.1, claude-sonnet-4) and exponential (gpt-4o, llama-4-scout). Models are biased toward earlier instructions — [arXiv 2507.11538](https://arxiv.org/html/2507.11538v1)
- Within-session compliance decays by about 5.6% in odds per generated function, with median first omission at function 4 — [arXiv 2605.10039](https://arxiv.org/pdf/2605.10039)
- Anthropic's Claude prompting best-practices guidance says newer Claude models (from 4.5 on) respond more strongly to system prompts. Prompts written to fight under-triggering ("CRITICAL: You MUST use this tool when…") now cause over-triggering, so the advice is to use normal phrasing and conditional "use X when Y" instructions — [Claude prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices) (quoted via [prosperinai summary](https://prosperinai.substack.com/p/official-claude-prompting-everything); the official passage was not seen directly)
- Context files raise inference cost by more than 20% without improving success, and agents follow the instructions in them literally — [arXiv 2602.11988](https://arxiv.org/abs/2602.11988)
- Critique of Superpowers, the closest analogue to OAC: the top criticism is "bloated rather than wrong", along with doubts about paying a harness token tax on models that plan well, and the view that one always-on harness is "no longer the obvious default" — [mcp.directory, 2026](https://mcp.directory/blog/superpowers-skill-worth-it-2026). It is estimated at about 550 tokens of always-on skill listing plus a SessionStart hook injection — [buildthisnow](https://www.buildthisnow.com/blog/guide/mechanics/best-claude-code-skills-2026). A small 12-session benchmark reports 9% lower cost and 14% fewer tokens *with* Superpowers — [MindStudio](https://www.mindstudio.ai/blog/5-claude-code-skills-cut-token-costs-70-percent-benchmarked) (anecdotal; methodology unverified)
- Harness fit is model-specific. GPT did best under a minimal scaffold (PI), while Kimi needed a harness that catches malformed tool calls — [arXiv 2610.00917](https://arxiv.org/html/2610.00917v1)
- Results are tied to model versions, a limitation the context-file studies state explicitly — [arXiv 2607.27250](https://arxiv.org/html/2607.27250v1)

### Inferences
- OAC's `using-oac` skill text ("requiring Skill tool invocation BEFORE ANY response… secret weapon") is exactly the shouting, coercive pattern that Anthropic says over-triggers on current Claude models. It also competes with host system prompts that set their own tool and skill policies. This is a likely source of unnecessary skill calls and of conflicts with the host.
- Mandatory multi-step flows (approach, then context discovery, then task breakdown) stack many instructions per turn. IFScale and the within-session decay results predict that adherence to *later* steps degrades, so these flows need evals that measure them, not assumptions.
- Model-version drift: prompts tuned for older, under-triggering models misbehave on newer ones. The eval suite should rerun on every model release.

### Gaps
- I found no controlled study isolating "MUST invoke skill" wording or SessionStart-hook injection effects.
- I found no study of conflicts between plugin prompts and host system prompts (Claude Code / Codex / OpenCode).

## Q4. Security and supply-chain concerns for distributing agents, skills and plugins

### Takeaway
Skills are now an active malware vector: the ClawHavoc campaign alone planted 1,184–1,200+ malicious skills in OpenClaw's ClawHub during Jan–May 2026. Skill files carry semantic prompt injection that code scanners miss, and metadata alone can hijack skill selection. Treat distributed skills and context files as executable code that needs provenance, review and scanning.

### Cited Findings
- **ClawHavoc** (Jan–Feb 2026): more than 1,200 malicious skills in the OpenClaw marketplace deploying the AMOS credential stealer — [arXiv 2607.13987, Agent Skill Security](https://arxiv.org/pdf/2607.13987) (snippet). The Cloud Security Alliance confirmed 1,184+ malicious ClawHub skills distributing Atomic macOS Stealer between Feb and May 2026 and argues that traditional code scanning misses the semantic attack surface — [CSA research note, 24 Jun 2026](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-skill-supply-chain-attacks-20260624-csa/)
- Palo Alto Unit 42: after ClawHub added VirusTotal and ClawScan screening, evasive skills persisted (Feb–May review), including 5 that were not blocked, 2 of them using novel agentic techniques for financial gain — [Unit 42](https://unit42.paloaltonetworks.com/openclaw-ai-supply-chain-risk/)
- Payload-less, metadata-only attacks skew skill discovery and selection — [arXiv 2605.14460](https://arxiv.org/pdf/2605.14460), via [CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-skill-supply-chain-attacks-20260624-csa/)
- SkillsMP lists more than 631,000 skills with no mandatory security review. Optimized injections in skills reach a 95.1% attack success rate vs 10.9% for naive ones. A Snyk study is reported to have found prompt injection in 36% of skills examined and 1,467 malicious payloads — [arXiv 2604.03081](https://arxiv.org/html/2604.03081v1), [arXiv 2609.14079 SkillSecurer](https://arxiv.org/pdf/2609.14079) (snippet; the figures come from different methods)
- MCP tool poisoning (CVE-2025-54136): attacker-written tool descriptions act as instructions to the model — [CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-skill-supply-chain-attacks-20260624-csa/)
- Defensive tools: SkillSieve — [arXiv 2604.06550](https://arxiv.org/pdf/2604.06550); MalSkills — [arXiv 2603.27204](https://arxiv.org/pdf/2603.27204); SkillSecurer — [arXiv 2609.14079](https://arxiv.org/pdf/2609.14079); Cisco's open-source skill scanner; a formal Dolev–Yao-style attacker model for the skill lifecycle — [arXiv 2603.00195](https://arxiv.org/html/2603.00195v1) (snippet)

### Inferences
- For OAC, context files installed from a registry are injected into the model's instructions, which makes them a prompt-injection channel just like skills. Registry content needs pinned versions, checksums or signatures, and diff review on update. Manual (not automatic) registry updates, which the repo already moved to, fit this guidance.
- Agent definitions that grant broad tools (Bash, Write) to subagents increase the blast radius of an injected context file. Least-privilege tool scopes per agent (for example, read-only scouts) are the mitigation.

### Gaps
- I found no authoritative 2026 source specifically on `curl | bash` installers for agent tooling. General supply-chain guidance applies, but it was not retrieved here.
- Official Anthropic, OpenAI and Cursor guidance on plugin signing, permission scopes or marketplace review was not retrieved.
